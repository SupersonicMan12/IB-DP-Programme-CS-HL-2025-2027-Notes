Diagrammatic representation of linked list
![[Pasted image 20260609092610.png]]![[Screenshot 2026-06-09 at 09.26.15.png]]

Intuition: each element points to the next, and may point to the previous. How to:
- Insert O(n): originally a to c. Point a to b, b to c.
- Delete O(n): originally a to b to c. Point a to c.
- Traverse O(n): traverse from head to tail:
	- `x = x.nxt`
- Search O(n), basically traverse and check.

Implementation of doubly linked list:
```java
public class Student {
    public String name;
    public int age;
    public Student nextStudent;
    public Student prevStudent;
    public Student(String _name, int _age) {
        name = _name;
        age = _age;
        nextStudent = null;
        prevStudent = null;
    }
}
// sentinel nodes
Student head = new Student("", -1);
Student tail = new Student("", -1);

public void initialize(){
    head.nextStudent = tail;
    tail.prevStudent = head;
}

// delete student x from the linked list
public void delete(Student x) {
    x.prevStudent.nextStudent = x.nextStudent;
    x.nextStudent.prevStudent = x.prevStudent;
    x.nextStudent = null;
    x.prevStudent = null;
}

// insert student x after student y
// notice first change x, then its neighbors!
public void insert(Student x, Student y) {
    x.nextStudent = y.nextStudent;
    x.prevStudent = y;
    y.nextStudent.prevStudent = x;
    y.nextStudent = x;
}

// returns age of a queried student, O(n)
public int find(String targetName) {
    Student curr = head.nextStudent;
    while (curr != tail) {
        if (curr.name.equals(targetName)) {
            return curr.age;
        }
        curr = curr.nextStudent;
    }
    return -1;
}
```

Binary search trees allow for binary searching: for each node $x$, it is $\ge$ all nodes in its left child's subtree and $\le$ all nodes in its right child's subtree. A sketch:
![[Screenshot 2026-06-09 at 18.16.37.png]]

Necessary operations:
- Insert O(log n) average O(n) worst
- Delete O(log n) average O(n) worst
- Traverse O(n)
- Search O(log n) average O(n) worst

Inorder: ABCDEFC
Preorder: DBACFEG
Postorder: ACBEGFD

Do not need to know the exact implementation, just know the idea:
```java
public class Node {
	public int id;
    public String name;
    public Node leftChild;
    public Node rightChild;
    public Node(int _id, String _name) {
        id = _id_
        name = _name;
        leftChild = null;
        rightChild = null;
    }
}
public Node root = null;

// to insert, call "root = insert(root, ID, NAME)"
// the function returns the root of the edited subtree
public Node insert(Node curr, int id, String name){
	if (curr == null){
		return new Node(id, name);
	}
	if (id <= curr.id){
		curr.leftChild = insert(curr.leftChild, id, name);
	} else {
		curr.rightChild = insert(curr.rightChild, id, name);
	}
	return curr;
}

public String search(Node curr, int id){
	if (curr == null){
		return "NOT FOUND!!";
	}
	if (curr.id == id){
		return curr.name;
	}
	if (id <= curr.id){
		return search(curr.leftChild, id);
	} else {
		return search(curr.rightChild, id);
	}
}

public Node findMin(Node curr){
	if (curr.leftChild != null) return findMin(curr.leftChild);
	else return curr;
}

// again, the function returns the root of the edited subtree
// to delete, call "root = delete(root, id)"
public Node delete(Node curr, int id){
	if (curr == null){
		return null; // NOT FOUND
	}
	if (id < curr.id){
		curr.leftChild = delete(curr.leftChild, id);
	} else if (id > curr.id) {
		curr.rightChild = delete(curr.rightChild, id);
	} else {
		// we found the node we want to delete
		// 0 children
		if (curr.leftChild == null && curr.rightChild == null){
			return null;
		} 
		// 1 child
		else if (curr.leftChild == null){
			return curr.rightChild;
		} else if (curr.rightChild == null){
			return curr.leftChild;
		} 
		// 2 children!
		else {
			// importantly, if both exist:
			Node successor = findMin(curr.rightChild);
			curr.id = successor.id;
			curr.name = successor.name;
			curr.rightChild = delete(curr.rightChild, successor.id);
		}
	}
	return curr;
}

// PROBABLY MOST IB-RELEVANT!!
public void in_traverse(Node curr){
	// remember: LEFT ME RIGHT
	if (curr.leftChild != null) traverse(curr.leftChild);
	System.out.println(curr.id + ": " + curr.name);
	if (curr.rightChild != null) traverse(curr.rightChild);
}

public void pre_traverse(Node curr){
	// remember: LEFT ME RIGHT
	System.out.println(curr.id + ": " + curr.name);
	if (curr.leftChild != null) traverse(curr.leftChild);
	if (curr.rightChild != null) traverse(curr.rightChild);
}

public void post_traverse(Node curr){
	// remember: LEFT ME RIGHT
	if (curr.rightChild != null) traverse(curr.rightChild);
	if (curr.leftChild != null) traverse(curr.leftChild);
	System.out.println(curr.id + ": " + curr.name);
}

```

## B4.1.6 Explain the core principles of ADTs. 
- High-level description of data structures and their associated operations and purpose 
- The underlying mechanics of hash tables, including hashing functions, collision resolution strategies and load factors 
- The underlying mechanics of sets to store and manage data 
- HashMap and HashSet in Java; dict and set in Python

We explain the principles behind a hashset.

Hashing function H(x) is a deterministic function - meaning same x results in same H(x) and hence if x = y, there must be H(x) = H(y). A good hashing function should also have:
- uniform distribution
- and be efficient in computation

A hash table = hash value + key(s)
![[Screenshot 2026-06-09 at 19.31.44.png]]

Usually, the Range of H(x) < Domain of H(x), meaning there will be x != y that have H(x) = H(y), we call this **collision**. To resolve this, we have:
- Chaining: for each hash value H(x), which may correspond to multiple initial keys, we store a chain of keys per hash value.
- Open addressing: when a collision occurs, we keep trying values until unoccupied:
	- Linear probing, keep adding 1
	- Quadratic probing, add by $x^2$.
	- Double hashing: the addition interval is a constant is determined by a second hash function

Load factor = how full the hash table is: $\lambda = \cfrac{\text{number of entries}}{\text{total number of bucks}}$. If this is high, we end up dealing with a lot of collisions

Rehashing = getting a new, larger array when $\lambda$ is too large.
