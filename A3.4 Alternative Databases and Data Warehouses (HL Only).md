- Examples of the use of the database model in real-world scenarios may include e-commerce platforms, geographic information systems (GIS), managed services, real-time analytics, social media platforms, SaaS.


| Model     | What                                                                                              | Why                                                                                | Disadvantages              | Example                                                     |
| --------- | ------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- | -------------------------- | ----------------------------------------------------------- |

## A3.4.2 Explain the primary objectives of data warehouses in data management and business intelligence.
- The roles of append-only data, subject-oriented data, integrated data, time-variant data, non-volatile data and data optimized for query performance, to ensure efficient data storage and analysis

Data warehouse = a central store that collects historical data from many operational systems (sales DB, HR DB, web logs) and reorganizes it for analysis rather than day-to-day transactions


| Operational DB (OLTP)                      | Data warehouse (OLAP)                                                  |
| ------------------------------------------ | ---------------------------------------------------------------------- |
| Current data, many small read/writes       | Historical data, a few large reads                                     |
| Normalized (3NF) to avoid update anomalies | Denormalized (star schema) for fast queries — the **A3.2.7** trade-off |
| "Process this order"                       | "How did sales trend by region over 5 years?"                          |
The data stored in data warehouses have six roles for **business intelligence**, giving decision-makers one trusted, historical, consistent source to analyze without slowing down the live systems. 
- Append-only — once loaded, data is not changed or deleted by users, we are keeping a history
- Subject-oriented: organized around business subjects, not applications/processes
- Integrated — data from different sources is cleaned and made consistent (same units, formats, codes) before loading (ETL: extract, transform, load)
- Time-variant — every record is time-stamped; keeps history so trends can be analyzed
- Non-volatile — once loaded, data is not changed or deleted by users
- Optimized for query performance — denormalized, heavily indexed and pre-aggregated (think views from A3.3.5)
## A3.4.3 Explain the role of online analytical processing (OLAP) and data mining for business intelligence.
* Data mining techniques must include classification, clustering, regression, association rule discovery, sequential pattern discovery, anomaly detection (note: This links to “A4 Machine learning”).
* The uses of the techniques in extracting meaningful information from large data sets

Both OLAP and Data Mining are ways to feed decisions / provide **business intelligence**.

**OLAP (online analytical processing)** = interactive analysis of warehouse data across multiple dimensions (time x region x product = a "data cube"). **Human asks the questions**:
- Roll-up = move up the hierarchy, summarize
- Drill-down = move down the hierarchy, specify
- Slice = fix one dimension
- Pivot = rotate axes

**Data Mining**: nobody asked. **Humans don't explicitly ask the questions**. Machine finds the pattern:
- Classification: assign a record to a known category
- Clustering: groups similar records with no predefined categories
- Regression: predict a continuous number by finding a function that models the given data points well
- Association rule discovery: "items that occur together", association of people who drink beer and people who are German
- Sequential pattern discovery: association over time, consumers who buy a phone buy a case within 2 weeks
- Anomaly detection: find records that don't fit the pattern, ie.g. credit card fraud or network intrusion

## A3.4.4 Describe the features of distributed databases.
- The need to maintain data consistency in a distributed database
- The role of ACID to ensure reliable processing of transactions in distributed databases
- Features of distributed databases: concurrency control, data consistency, data partitioning, data security, distribution transparency, fault tolerance, global query processing, location transparency, replication, scalability

Distributed database = one logical database whose data is physically stored on several computers (nodes), possibly in different locations, but appears to the user as a single database

Two problems:
- Consistency — the same data may exist on several nodes; if one copy is updated and the other is not, users get inconsistent answers. Keeping copies in step requires coordination protocols
- ACID across nodes — a transaction may touch tables on different machines; atomicity means all nodes commit or all roll back, even if the network fails halfway. Much harder than on one machine. 

Ten features, grouped to help memorize:

**Where the data goes**
Data partitioning (fragmentation) — split a table across nodes
Replication — copies of the same data on several nodes for speed and clarity

**Illusion of one database**
Distribution transparency — user doesn't know where data is split
Location transparency — user doesn't need to know which node holds it
Global query processing — one query is decomposed, run on the relevant nodes, and results merged

**Correctness**
Concurrency control — locking / timestamps so simultaneous transactions on different nodes don't corrupt data
Data consistency — all copies agree
Data security — access control and encryption at every node and on the network between them

**Why Bother**
Fault tolerance — if one node fails, replicas keep the system running
Scalability — add nodes to handle more data/users (horizontal scaling)
