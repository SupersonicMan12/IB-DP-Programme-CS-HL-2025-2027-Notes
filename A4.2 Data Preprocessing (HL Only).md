## A4.2.1 Describe the significance of ==data cleaning==.
- The impact of data quality on model performance
- ==Techniques== for ==handling== outliers, removing or consolidating duplicate data, identifying incorrect data, filtering irrelevant data, transforming improperly formatted data, and imputation, deletion or predictive modelling for missing data
- ==Normalization and standardization== as crucial preprocessing steps


> [!QUOTE] "Garbage in, garbage out"
> Poor-quality data gives an inaccurate, biased model that won't generalize
> - Claude Opus 5.5, Oct. 26, 2026

| Problem                       | How to handle it                                                                                                                                                                              |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Outliers**                  | Detect them (z-score, IQR, plots), then remove them, cap them, or keep them if they are genuine                                                                                               |
| **Duplicates**                | Remove them or merge them into one record; otherwise they ==over-weight== some examples                                                                                                       |
| **Incorrect data**            | Validation checks for impossible values (e.g. age = −5) and range checks; then fix or remove                                                                                                  |
| **Irrelevant data**           | Filter out records or features that don't relate to the problem                                                                                                                               |
| **Improperly formatted data** | Make it consistent: dates, units, capitalization, data types                                                                                                                                  |
| **Missing data**              | **Deletion:** drop the row or column (risks losing information). **Imputation:** fill in the mean, median or mode. **Predictive modeling:** predict the missing value from the other features |
**Normalization**: rescales values to a fixed range
$$x^* = \frac{x-x_{min}}{x_{max}-x_{min}}$$
Standardization rescales to mean $0$ and standard deviation $1$. 
$$x^* = \frac{x-\phi}{\sigma}$$
= z-score, which copes better with outliers

## A4.2.2 Describe the role of feature selection.
- Feature selection to identify and retain the most informative attributes of the data set
- Feature selection strategies: filter methods, wrapper methods, embedded methods

We keep only the most informative features and drop irrelevant or redundant ones, leading to less overfitting, faster training, simpler and more interpretable models:
- **Filter**: scores each feature with a statistical test (e.g. correlation with target) before and independently of the model
- **Wrapper**: trains the model on different subsets of features and keeps the best-performing subset (expensive)
- **Embedded**: selection happens during training as part of the algorithm
## A4.2.3 Describe the importance of dimensionality reduction.
- The curse of dimensionality considerations may include overfitting, computational complexity, data sparsity, the effectiveness of distance metrics, data visualization, sample size increases, memory usage.
- Dimensionality reduction of variables, while preserving the relevant aspects of the data
- Note: Statistical techniques such as principal component analysis (PCA) and linear discriminant analysis (LDA) are beyond the scope of this course.

Curse of dimensionality: as the number of features grows, the data space grows exponentially, so the data becomes sparse, causing:
- **Overfitting**: with many features, the model fits noise
- **Computational complexity**: training takes more time
- **Memory usage** goes up; **sample size**: needs to grow exponentially to cover the space
- **Data sparsity**: points are spread far apart...
- **Distance metrics** become less effective because all points become similarly distant, breaking KNN and K-means
- **Visualization**: beyond 3 dimensions, the data can't be plotted

**Dimensionality reduction** cuts the number of variables while keeping the relevant information, either by selecting features or by combining them into fewer ones
